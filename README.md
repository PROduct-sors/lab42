# Лабораторна робота: Налаштування Redux та робота з DevTools

## Відповіді на контрольні питання:

1. **Які файли/модулі входять до мінімальної структури Redux-проєкту?**
   Мінімальна структура включає: `store.js` (сховище), `reducers.js` (функції оновлення стану), `actions.js` (опис дій). Також потрібен компонент `Provider` з бібліотеки `react-redux` для підключення стора до React.

2. **Чим dispatch відрізняється від виклику функції reducer напряму?**
   Виклик reducer напряму просто повертає новий об'єкт, але Redux про це не дізнається. `dispatch` — це спеціальний тригер, який відправляє дію (action) у Redux Store, викликає reducer під капотом, оновлює глобальний стан і змушує React-компоненти перемалюватись.

3. **Навіщо потрібен компонент Provider і де його розміщують?**
   `Provider` робить Redux Store доступним для всіх вкладених компонентів (через React Context). Його розміщують на самому верху дерева застосунку (зазвичай обгортають `<App />` у файлi `main.jsx` або `index.js`).

4. **Що показує вкладка «⚛️ Components» у React DevTools?**
   Вона показує дерево React-компонентів, поточні значення їхніх `props`, локальний `state` (useState) та активні хуки конкретного компонента.

5. **Чим Redux DevTools відрізняється від React DevTools?**
   React DevTools призначений для інспектування UI-дерева та локального стану компонентів. Redux DevTools відстежує глобальний стан, логує історію всіх виконаних дій (actions) і показує, як саме кожна дія змінила стан (Diff).

6. **Що таке time-travel debugging і завдяки чому він можливий?**
   Це можливість "перемотувати" стан додатка назад і вперед у часі, скасовуючи або повторюючи дії. Це можливо виключно тому, що Redux reducers — це *чисті функції* (pure functions), які не мутують старий стан, а завжди створюють новий.

7. **Чому вимикають devTools у production?**
   По-перше, для оптимізації продуктивності (DevTools споживають багато пам'яті). По-друге, з міркувань безпеки, щоб користувачі не могли бачити внутрішню логіку додатка та глобальний стан (де можуть бути токени чи дані користувачів).

8. **Що покаже вкладка Diff у Redux DevTools після дії RESET?**
   Вона покаже, що поле `count` змінилося з його попереднього значення (наприклад, з `3`) на `0`.

9. **Чим налаштування DevTools через Redux Toolkit простіше?**
   У "класичному" Redux потрібно було вручну прописувати підключення розширення (`window.__REDUX_DEVTOOLS_EXTENSION__`). У Redux Toolkit DevTools увімкнені автоматично "з коробки" при використанні `configureStore`.

10. **Як побачити в Redux DevTools, що саме прийшло у payload дії?**
    Потрібно обрати конкретну дію у лівій панелі Redux DevTools і перейти на вкладку **Action** у правій панелі. Там буде відображено об'єкт дії з полями `type` та `payload`.
